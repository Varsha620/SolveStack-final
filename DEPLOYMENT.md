# SolveStack Deployment Guide

The frontend is already deployed here:

```text
https://varsha620.github.io/SolveStack-final/
```

The remaining step for a full-stack deployment is hosting the FastAPI backend and PostgreSQL database.

## Recommended Option: Render

This repo includes `render.yaml`, so Render can create:

- `solvestack-api` FastAPI web service
- `solvestack-db` PostgreSQL database

### Steps

1. Go to Render and create a new Blueprint from the GitHub repository:

   ```text
   Varsha620/SolveStack-final
   ```

2. Render should detect `render.yaml`.

3. Confirm these backend settings:

   ```text
   Root directory: SolveStack-main
   Build command: pip install -r requirements-deploy.txt
   Start command: uvicorn main:app --host 0.0.0.0 --port $PORT
   ```

4. Confirm environment variables:

   ```text
   ENVIRONMENT=production
   SECRET_KEY=<auto-generated or manually generated>
   FRONTEND_ORIGINS=https://varsha620.github.io
   DATABASE_URL=<from hosted PostgreSQL>
   SEED_DEMO_DATA=true
   ```

5. After the backend deploys, open:

   ```text
   https://your-render-service.onrender.com/
   https://your-render-service.onrender.com/docs
   ```

6. If you did not set `SEED_DEMO_DATA=true`, seed demo data in the backend shell:

   ```bash
   python seed_demo_data.py
   ```

7. Update frontend deployment to use the backend:

   In GitHub Actions or frontend environment:

   ```text
   VITE_API_URL=https://your-render-service.onrender.com
   VITE_WS_URL=
   VITE_DEMO_MODE=fallback
   ```

   Re-run the frontend Pages deployment after changing this.

## Railway Option

Railway can also deploy this backend.

Use:

```text
Root directory: SolveStack-main
Install command: pip install -r requirements-deploy.txt
Start command: uvicorn main:app --host 0.0.0.0 --port $PORT
```

Add a PostgreSQL database plugin and set:

```text
DATABASE_URL=<Railway PostgreSQL connection string>
ENVIRONMENT=production
SECRET_KEY=<strong generated secret>
FRONTEND_ORIGINS=https://varsha620.github.io
```

Then run:

```bash
python seed_demo_data.py
```

## Why `requirements-deploy.txt` Exists

The full `requirements.txt` includes local AI/embedding packages such as PyTorch and sentence-transformers. Those are useful for advanced semantic search locally, but they make free-tier deployment slow and fragile.

`requirements-deploy.txt` keeps the hosted demo backend lightweight. Search endpoints fall back to database keyword search when embedding packages are not installed.
